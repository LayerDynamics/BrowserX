## Core Modules

<CardGrid stagger>
  <Card title="Browser Engine" icon="laptop">
    Full page load pipeline from DNS to pixels. HTML/CSS parsing, JavaScript execution via V8, network stack (TCP/TLS/HTTP), and WebGPU-accelerated rendering.

    [Browser Engine docs](/browser/)
  </Card>
  <Card title="Proxy Engine" icon="random">
    Traffic routing with a layered middleware pipeline. Supports reverse proxying, load balancing, caching (LRU/LFU/FIFO), connection pooling, and distributed tracing.

    [Proxy Engine docs](/proxy/)
  </Card>
  <Card title="Query Engine" icon="magnifier">
    SQL-like interface for browser and proxy operations — readable by humans and AI agents alike.

    [Query Engine docs](/query/)
  </Card>
  <Card title="Runtime" icon="puzzle">
    Unified orchestration layer that composes the browser, proxy, and query engines into coordinated workflows with lifecycle management, plugin system, and health checking.

    [Runtime docs](/runtime/)
  </Card>
  <Card title="MCP Server" icon="robot">
    Model Context Protocol server for AI-driven browser control. Exposes browser tools, resources, and prompts over stdio or HTTP for LLM integration.

    [MCP Server docs](/mcp/)
  </Card>
</CardGrid>

## Query Syntax at a Glance

BrowserX provides a SQL-like query language for browser automation:

```sql
-- Extract data from a page
SELECT title, description FROM "https://example.com"

-- Navigate with custom headers and capture the response
NAVIGATE TO "https://api.example.com"
  WITH { headers: { "Authorization": "Bearer token" } }
  CAPTURE response.body, dom.title

-- Conditional form interaction
IF EXISTS("#login-form") THEN
  INSERT "user@example.com" INTO "#email"
  CLICK "#submit"
END
```

See the [Query Engine docs](/query/) for the full syntax reference.
