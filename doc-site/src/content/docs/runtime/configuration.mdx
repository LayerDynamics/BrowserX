The BrowserX Runtime provides comprehensive configuration options for all subsystems. Configuration can be provided when creating the runtime or through preset factory functions.

## Configuration Structure

```typescript
interface BrowserXRuntimeConfig {
  environment: "development" | "production" | "test";
  logLevel: "debug" | "info" | "warn" | "error";
  browser: BrowserPoolConfig;
  proxy: ProxyEngineConfig;
  query: QueryEngineConfig;
  eventLoop: EventLoopConfig;
  shutdown: ShutdownConfig;
  signals: SignalConfig;
  metrics: MetricsConfig;
  plugins: PluginConfig;
}
```

## Browser Pool Configuration

Controls browser instance pooling and lifecycle:

```typescript
interface BrowserPoolConfig {
  minInstances: number;        // Minimum warm instances (default: 0)
  maxInstances: number;        // Maximum concurrent instances (default: 10)
  idleTimeout: number;         // Close idle instances after ms (default: 1800000)
  maxLifetime: number;         // Max instance lifetime ms (default: 3600000)
  defaultWidth: number;        // Viewport width (default: 1280)
  defaultHeight: number;       // Viewport height (default: 720)
  enableJavaScript: boolean;   // Enable JS execution (default: false)
  enableStorage: boolean;      // Enable storage APIs (default: true)
  devicePixelRatio: number;    // Screenshot pixel ratio (default: 1.0)
}
```

### Resource Management

The browser pool automatically manages resources:

- **Idle Timeout**: Instances idle for longer than `idleTimeout` are closed (respects `minInstances`)
- **Max Lifetime**: Instances older than `maxLifetime` are rotated out (prevents memory leaks)
- **Pre-warming**: `minInstances` warm instances are created on startup
- **Cleanup Intervals**: Idle cleanup runs every 60 seconds, lifetime check every 5 minutes

## Proxy Engine Configuration

Controls the proxy engine subsystem:

```typescript
interface ProxyEngineConfig {
  enabled: boolean;                   // Enable proxy engine (default: false)
  gateways: ProxyGatewayConfig[];     // Gateway server configs
  gracefulShutdownTimeout: number;    // Shutdown timeout ms (default: 30000)
  metrics: boolean;                   // Enable proxy metrics (default: false)
  metricsPort?: number;               // Proxy metrics port
  metricsHost?: string;               // Proxy metrics host
}

interface ProxyGatewayConfig {
  host: string;                       // Gateway listen host
  port: number;                       // Gateway listen port
  tls?: {
    certFile: string;                 // TLS certificate path
    keyFile: string;                  // TLS private key path
    alpnProtocols?: string[];         // ALPN protocols (e.g., ["h2", "http/1.1"])
  };
  routes?: Array<{
    pathPattern: string;              // Route path regex (e.g., "/api/.*")
    targetHost: string;               // Upstream host
    targetPort: number;               // Upstream port
  }>;
}
```

### Example: Reverse Proxy

```typescript
{
  proxy: {
    enabled: true,
    gateways: [
      {
        host: "0.0.0.0",
        port: 8080,
        routes: [
          {
            pathPattern: "/api/.*",
            targetHost: "backend.example.com",
            targetPort: 3000,
          },
          {
            pathPattern: "/static/.*",
            targetHost: "cdn.example.com",
            targetPort: 443,
          },
        ],
      },
    ],
    gracefulShutdownTimeout: 30000,
    metrics: true,
    metricsPort: 9091,
  }
}
```

### Example: TLS Termination

```typescript
{
  proxy: {
    enabled: true,
    gateways: [
      {
        host: "0.0.0.0",
        port: 443,
        tls: {
          certFile: "/path/to/cert.pem",
          keyFile: "/path/to/key.pem",
          alpnProtocols: ["h2", "http/1.1"],
        },
        routes: [
          {
            pathPattern: ".*",
            targetHost: "localhost",
            targetPort: 8080,
          },
        ],
      },
    ],
  }
}
```

## Event Loop Configuration

Controls event loop coordination:

```typescript
interface EventLoopConfig {
  enabled: boolean;                   // Enable event coordination (default: true)
  targetFrameRate: number;            // Browser loop frame rate (default: 60)
  maxMicrotasksPerCycle: number;      // Max microtasks per tick (default: 1000)
  enableIdleTasks: boolean;           // Enable idle task processing (default: true)
}
```

### Frame Rate Impact

The `targetFrameRate` controls browser event loop tick frequency:

- **60 FPS** (default): Smooth animations, responsive UI (16.67ms per frame)
- **30 FPS**: Lower CPU usage, still acceptable for most UIs (33.33ms per frame)
- **15 FPS**: Minimal CPU, noticeable lag in animations (66.67ms per frame)

```typescript
{
  eventLoop: {
    enabled: true,
    targetFrameRate: 30,              // 30 FPS for lower CPU usage
    maxMicrotasksPerCycle: 500,       // Lower limit for slower machines
    enableIdleTasks: false,           // Disable idle tasks in production
  }
}
```

## Shutdown Configuration

Controls graceful shutdown behavior:

```typescript
interface ShutdownConfig {
  graceful: boolean;                  // Enable graceful shutdown (default: true)
  timeout: number;                    // Total shutdown timeout ms (default: 30000)
  drainTimeout: number;               // Connection drain timeout ms (default: 5000)
  forceExitOnTimeout: boolean;        // Force exit after timeout (default: true)
}
```

### Shutdown Sequence

When `graceful: true`, the runtime performs ordered shutdown:

1. **Plugin Manager**: Deactivate plugins in reverse activation order
2. **Query Engine**: Abort running queries, flush caches
3. **Proxy Engine**: Drain active connections, stop accepting new requests
4. **Browser Pool**: Close all browser instances
5. **Event Coordinator**: Stop all event loops
6. **Metrics Collector**: Stop metrics server, export final metrics

```typescript
{
  shutdown: {
    graceful: true,
    timeout: 60000,                   // 1 minute total
    drainTimeout: 10000,              // 10 seconds to drain connections
    forceExitOnTimeout: true,         // Exit if timeout exceeded
  }
}
```

## Signal Handling Configuration

Controls OS signal handling:

```typescript
interface SignalConfig {
  handleSIGINT: boolean;              // Handle Ctrl+C (default: true)
  handleSIGTERM: boolean;             // Handle SIGTERM (default: true)
  handleSIGHUP: boolean;              // Handle SIGHUP (default: false)
}
```

When signal handling is enabled, the runtime automatically initiates graceful shutdown on signal receipt.

```typescript
{
  signals: {
    handleSIGINT: true,               // Ctrl+C triggers shutdown
    handleSIGTERM: true,              // systemd stop triggers shutdown
    handleSIGHUP: false,              // Ignore SIGHUP
  }
}
```

## Plugin Configuration

Controls the plugin system:

```typescript
interface PluginConfig {
  enabled: boolean;                   // Enable plugin system (default: false)
  pluginDirs: string[];               // Directories to scan for plugins
  plugins: PluginEntry[];             // Explicit plugin entries
  activationTimeout: number;          // Plugin activation timeout ms (default: 10000)
}

interface PluginEntry {
  path: string;                       // Plugin module path or URL
  enabled: boolean;                   // Whether to activate this plugin
  config?: Record<string, unknown>;   // Plugin-specific configuration
}
```

## Environment Variables

Configuration can be overridden via environment variables:

```bash
# Browser pool
BROWSERX_BROWSER_MAX_INSTANCES=20
BROWSERX_BROWSER_IDLE_TIMEOUT=600000

# Proxy
BROWSERX_PROXY_ENABLED=true
BROWSERX_PROXY_PORT=8080

# Metrics
BROWSERX_METRICS_ENABLED=true
BROWSERX_METRICS_PORT=9090

# Plugins
BROWSERX_PLUGINS_ENABLED=true
BROWSERX_PLUGINS_DIR=./plugins
```

Load environment variables with a custom config loader:

```typescript
function loadConfigFromEnv(): Partial<BrowserXRuntimeConfig> {
  return {
    browser: {
      maxInstances: parseInt(process.env.BROWSERX_BROWSER_MAX_INSTANCES ?? "10"),
      idleTimeout: parseInt(process.env.BROWSERX_BROWSER_IDLE_TIMEOUT ?? "1800000"),
    },
    metrics: {
      enabled: process.env.BROWSERX_METRICS_ENABLED === "true",
      port: parseInt(process.env.BROWSERX_METRICS_PORT ?? "9090"),
    },
  };
}

const runtime = new BrowserXRuntime({
  config: mergeConfig(loadConfigFromEnv()),
});
```

## Configuration Validation

The Runtime validates configuration on startup:

```typescript
import { ConfigValidator } from "@browserx/runtime/config/ConfigValidator.ts";

const validator = new ConfigValidator();
const errors = validator.validate(config);

if (errors.length > 0) {
  console.error("Configuration errors:", errors);
  throw new Error(`Invalid configuration: ${errors.join(", ")}`);
}
```

Common validation errors:

- `browser.maxInstances` must be > 0
- `browser.minInstances` must be ≤ `maxInstances`
- `browser.idleTimeout` must be > 0
- `browser.maxLifetime` must be > `idleTimeout`
- `shutdown.timeout` must be ≥ `shutdown.drainTimeout`
- `plugins.activationTimeout` must be > 0
